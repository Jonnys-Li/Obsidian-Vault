# 第15天：视图生命周期基础

## 核心知识点总结

### 1. UIViewController 生命周期方法

#### 视图加载阶段
- `loadView` - 创建视图层次结构（如果使用代码创建视图）
- `viewDidLoad` - 视图加载完成，只调用一次
- `viewWillAppear:` - 视图即将显示
- `viewDidAppear:` - 视图已经显示
- `viewWillDisappear:` - 视图即将消失
- `viewDidDisappear:` - 视图已经消失

#### 调用顺序
```
loadView → viewDidLoad → viewWillAppear: → viewDidAppear:
→ viewWillDisappear: → viewDidDisappear:
```

### 2. 各生命周期方法的用途

#### viewDidLoad
- **调用时机**：视图加载完成后，只调用一次
- **用途**：初始化数据、设置UI、注册通知等
- **注意**：此时视图的frame可能还未确定

#### viewWillAppear:
- **调用时机**：视图即将显示到屏幕上
- **用途**：刷新数据、开始动画、显示导航栏等
- **特点**：每次显示都会调用

#### viewDidAppear:
- **调用时机**：视图已经完全显示
- **用途**：开始网络请求、埋点统计、启动定时器等
- **特点**：每次显示都会调用

#### viewWillDisappear:
- **调用时机**：视图即将消失
- **用途**：保存数据、停止动画、暂停定时器等
- **特点**：每次消失都会调用

#### viewDidDisappear:
- **调用时机**：视图已经完全消失
- **用途**：清理资源、停止网络请求等
- **特点**：每次消失都会调用

### 3. 特殊场景

#### 内存警告
- `didReceiveMemoryWarning` - 收到内存警告时调用
- `viewDidUnload` - iOS 6之前的方法，已废弃

#### 视图旋转
- `viewWillTransitionToSize:withTransitionCoordinator:` - 视图即将旋转
- `willRotateToInterfaceOrientation:duration:` - iOS 8之前的方法

## 面试题

### 基础题

#### 1. UIViewController的生命周期方法有哪些？调用顺序是什么？

**答案：**
主要生命周期方法：
1. `loadView` - 创建视图（如果使用代码）
2. `viewDidLoad` - 视图加载完成
3. `viewWillAppear:` - 视图即将显示
4. `viewDidAppear:` - 视图已经显示
5. `viewWillDisappear:` - 视图即将消失
6. `viewDidDisappear:` - 视图已经消失

调用顺序：
```
loadView → viewDidLoad → viewWillAppear: → viewDidAppear:
→ viewWillDisappear: → viewDidDisappear:
```

#### 2. viewDidLoad 和 viewWillAppear: 的区别是什么？

**答案：**
- **viewDidLoad**：
  - 只调用一次（视图加载时）
  - 适合做一次性的初始化工作
  - 此时视图的frame可能还未确定
  
- **viewWillAppear:**：
  - 每次视图显示前都会调用
  - 适合做每次显示都需要更新的工作
  - 此时视图的frame已经确定

#### 3. 在哪个生命周期方法中开始网络请求比较合适？

**答案：**
- **viewDidLoad**：适合加载基础数据，只加载一次
- **viewWillAppear:**：适合刷新数据，每次显示都刷新
- **viewDidAppear:**：适合加载非关键数据，避免阻塞视图显示

推荐在`viewDidAppear:`中开始网络请求，因为此时视图已经显示，用户体验更好。

#### 4. 什么时候使用 viewWillDisappear: 和 viewDidDisappear:？

**答案：**
- **viewWillDisappear:**：
  - 视图即将消失时调用
  - 适合保存数据、停止动画
  - 此时视图还在屏幕上，可以做一些清理工作
  
- **viewDidDisappear:**：
  - 视图已经完全消失
  - 适合清理资源、停止网络请求
  - 此时视图已不在屏幕上

### 进阶题

#### 5. loadView 方法的作用是什么？什么时候需要重写？

**答案：**
- **作用**：创建视图层次结构
- **默认行为**：从storyboard或xib加载视图
- **重写场景**：
  - 完全使用代码创建视图
  - 需要自定义视图创建逻辑
  - 不使用storyboard或xib

**注意**：
- 重写时必须创建`self.view`
- 不要调用`[super loadView]`（如果完全自定义）
- 不要在`loadView`中访问`self.view`的其他属性

#### 6. 视图控制器的生命周期在 push 和 present 时有什么区别？

**答案：**
- **Push（导航栈）**：
  - 新的ViewController入栈
  - 旧的ViewController不会调用`viewDidDisappear:`
  - 旧的ViewController的视图仍然在内存中
  
- **Present（模态展示）**：
  - 新的ViewController覆盖在旧的上面
  - 旧的ViewController会调用`viewWillDisappear:`和`viewDidDisappear:`
  - 旧的ViewController的视图可能被移除

#### 7. 如何处理内存警告？

**答案：**
```objc
- (void)didReceiveMemoryWarning {
    [super didReceiveMemoryWarning];
    
    // 清理不需要的资源
    // 释放缓存
    // 停止不必要的网络请求
}
```

**最佳实践**：
- 清理图片缓存
- 释放不需要的数据
- 停止后台任务
- 不要释放关键数据

#### 8. 视图旋转时的生命周期方法调用顺序是什么？

**答案：**
iOS 8+：
```
viewWillTransitionToSize:withTransitionCoordinator:
→ viewWillLayoutSubviews
→ viewDidLayoutSubviews
```

iOS 8之前：
```
willRotateToInterfaceOrientation:duration:
→ viewWillLayoutSubviews
→ viewDidLayoutSubviews
→ didRotateFromInterfaceOrientation:
```

### 原理题

#### 9. 为什么 viewDidLoad 只调用一次，而 viewWillAppear: 会多次调用？

**答案：**
- **viewDidLoad**：在视图加载到内存时调用，视图一旦加载就不会再次加载
- **viewWillAppear:**：在视图即将显示时调用，每次视图显示（包括从其他页面返回）都会调用

**设计原因**：
- 视图加载是一次性操作，所以`viewDidLoad`只调用一次
- 视图显示是多次操作（push、pop、present、dismiss），所以`viewWillAppear:`会多次调用

#### 10. 视图控制器的生命周期和视图的生命周期有什么区别？

**答案：**
- **视图控制器生命周期**：管理整个视图控制器的生命周期
- **视图生命周期**：管理单个视图的显示和隐藏

**关系**：
- 视图控制器的生命周期包含视图的生命周期
- 视图的生命周期方法在视图控制器的生命周期中调用
- 一个视图控制器可以管理多个视图（通过addChildViewController）

### 实操题2：演示不同场景下的生命周期调用

#### 需求描述
创建一个演示界面，包含多个按钮，演示push、present、dismiss等不同场景下的生命周期调用。

#### 实现步骤

1. **创建演示界面**
```objc
- (void)setupButtons {
    // Push按钮
    UIButton *pushButton = [self createButtonWithTitle:@"Push" action:@selector(pushViewController)];

    // Present按钮
    UIButton *presentButton = [self createButtonWithTitle:@"Present" action:@selector(presentViewController)];
    presentButton.frame = CGRectMake(100, 160, 200, 44);
    
    // Dismiss按钮（在presented的VC中）
    UIButton *dismissButton = [self createButtonWithTitle:@"Dismiss" action:@selector(dismissViewController)];
    dismissButton.frame = CGRectMake(100, 220, 200, 44);
    
    [self.view addSubview:pushButton];
    [self.view addSubview:presentButton];
    [self.view addSubview:dismissButton];
}
```

2. **实现不同场景的方法**
```objc
- (void)pushViewController {
    LifecycleDemoViewController *vc = [[LifecycleDemoViewController alloc] init];
    [self.navigationController pushViewController:vc animated:YES];
}

- (void)presentViewController {
    LifecycleDemoViewController *vc = [[LifecycleDemoViewController alloc] init];
    UINavigationController *nav = [[UINavigationController alloc] initWithRootViewController:vc];
    [self presentViewController:nav animated:YES completion:nil];
}

- (void)dismissViewController {
    [self dismissViewControllerAnimated:YES completion:nil];
}
```

#### 关键代码

```objc
// 在生命周期方法中输出详细信息
- (void)viewWillAppear:(BOOL)animated {
    [super viewWillAppear:animated];
    NSLog(@"%@ - viewWillAppear: %d, isMovingToParent: %d", 
          NSStringFromClass([self class]), 
          animated, 
          self.isMovingToParentViewController);
}

- (void)viewDidAppear:(BOOL)animated {
    [super viewDidAppear:animated];
    NSLog(@"%@ - viewDidAppear: %d, isMovingToParent: %d",
```

#### 观察要点
- Push时：新VC的`viewWillAppear:`和`viewDidAppear:`会调用，旧VC不会调用`viewDidDisappear:`
- Present时：新VC的`viewWillAppear:`和`viewDidAppear:`会调用，旧VC会调用`viewWillDisappear:`和`viewDidDisappear:`
- Dismiss时：当前VC会调用`viewWillDisappear:`和`viewDidDisappear:`

### 实操题3：在合适的生命周期方法中执行操作

#### 需求描述
演示在不同生命周期方法中执行不同操作的 best practice。

#### 实现步骤

1. **viewDidLoad - 一次性初始化**
```objc
- (void)viewDidLoad {
    [super viewDidLoad];
    
    // 设置UI
    self.view.backgroundColor = [UIColor whiteColor];
    self.title = @"生命周期最佳实践";
    
    // 初始化数据
    self.dataArray = [NSMutableArray array];
    
    // 注册通知
    [[NSNotificationCenter defaultCenter] addObserver:self 
                                               selector:@selector(handleNotification:) 
                                                   name:@"TestNotification" 
                                                 object:nil];
}
```

2. **viewWillAppear: - 每次显示时刷新**
```objc
- (void)viewWillAppear:(BOOL)animated {
    [super viewWillAppear:animated];
    
    // 刷新数据
    [self refreshData];
    
    // 显示导航栏
    [self.navigationController setNavigationBarHidden:NO animated:animated];
}
```

3. **viewDidAppear: - 开始网络请求和动画**
```objc
- (void)viewDidAppear:(BOOL)animated {
    [super viewDidAppear:animated];
    
    // 开始网络请求
    [self loadDataFromNetwork];
    
    // 开始动画
    [self startAnimation];
    
    // 埋点统计
    [self trackPageView];
}
```

4. **viewWillDisappear: - 保存数据和停止动画**
```objc
- (void)viewWillDisappear:(BOOL)animated {
    [super viewWillDisappear:animated];
    
    // 保存数据
    [self saveData];
    
    // 停止动画
    [self stopAnimation];
}
```

5. **viewDidDisappear: - 清理资源**
```objc
- (void)viewDidDisappear:(BOOL)animated {
    [super viewDidDisappear:animated];
    
    // 停止网络请求
    [self cancelNetworkRequest];
    
    // 清理临时数据
    [self clearTemporaryData];
}
```

#### 关键代码

```objc
- (void)dealloc {
    // 移除通知
    [[NSNotificationCenter defaultCenter] removeObserver:self];
    NSLog(@"%@ - dealloc", NSStringFromClass([self class]));
}
```

#### 最佳实践
- **viewDidLoad**：一次性初始化，设置UI，注册通知
- **viewWillAppear:**：刷新数据，显示/隐藏导航栏
- **viewDidAppear:**：开始网络请求，开始动画，埋点统计
- **viewWillDisappear:**：保存数据，停止动画
- **viewDidDisappear:**：停止网络请求，清理资源
- **dealloc**：移除通知，清理观察者

## 常见问题

### Q1: viewDidLoad 中能获取到视图的 frame 吗？

**A:** 
- 不一定，取决于视图的创建方式
- 如果使用storyboard或xib，通常可以获取到
- 如果使用代码创建，可能需要等到`viewDidLayoutSubviews`才能获取到正确的frame
- 建议在`viewDidLayoutSubviews`中获取frame

### Q2: 为什么 viewWillAppear: 会调用多次？

**A:**
- 每次视图显示时都会调用
- 包括：首次显示、从其他页面返回、present后dismiss等
- 这是正常行为，用于每次显示时刷新数据

### Q3: 在哪个方法中开始网络请求？

**A:**
- **viewDidLoad**：适合加载基础数据，只加载一次
- **viewWillAppear:**：适合刷新数据，每次显示都刷新
- **viewDidAppear:**：适合加载非关键数据，避免阻塞视图显示（推荐）

### Q4: 如何处理内存警告？

**A:**
- 在`didReceiveMemoryWarning`中清理不需要的资源
- 释放图片缓存
- 停止不必要的网络请求
- 不要释放关键数据
