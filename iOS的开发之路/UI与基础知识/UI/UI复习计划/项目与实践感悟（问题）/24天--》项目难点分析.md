## iOS 列表动画排查与解决思维导图

### 第一阶段：需求明确与基础搭建

- **初衷**：将 `UITableView` 设置为 `Grouped` 样式，并实现 Cell 进入屏幕时“从右向左”飞入。
    
- **关键知识点**：
    
    - `UITableViewStyle` 是只读的，必须在 `initWithStyle` 初始化时指定。
        
    - **Auto Layout 闭环**：通过 Masonry 建立 `top -> bottom` 的约束链，支撑起 `UITableViewAutomaticDimension`（自动行高）。
        

---

### 第二阶段：发现问题（动画“失踪”）

- **现象**：在 `willDisplayCell` 中设置了 `CGAffineTransform` 动画，代码逻辑正确，`NSLog` 显示动画已完成，但肉眼看不到效果。
    
- **分析链路**：
    
    1. **排除法**：确认 `cellForRow` 逻辑干净，排除逻辑冲突。
        
    2. **观测法**：利用 `NSLog` 打印 `finished` 状态。结果为 `1`，说明动画“跑过”了。
        
    3. **极端实验（结果B）**：删掉动画只留初始位移。发现 Cell 依然在原位。
        
- **核心结论**：**约束（Masonry）锁死了位置**。在 `willDisplayCell` 执行完后，系统触发了布局刷新，将 `transform` 产生的位移瞬间重置回了约束规定的位置。
    

---

### 第三阶段：多方案博弈与底层击破

我们尝试了三个层级的解决方案，这也是 iOS 解决 UI 问题的三个维度：

| **方案**   | **操作层级**                     | **结果**   | **思考**                                                    |
| -------- | ---------------------------- | -------- | --------------------------------------------------------- |
| **方案 A** | **UIView (Frame)**           | ❌ 失败     | 被 Auto Layout 强制重置，因为布局引擎权重高于简单的 UIView 属性。               |
| **方案 B** | **RunLoop (延时)**             | ⚠️ 不稳    | 通过 `dispatch_after` 绕过布局时机。虽然可能生效，但会产生闪烁，不符合高性能规范,体验感也不好。 |
| **方案 C** | **CALayer (Core Animation)** | ✅ **完美** | **降维打击**。直接在 GPU 渲染层做位移，不触碰布局引擎的 `Frame` 逻辑。              |

---

### 第四阶段：最终解法的底层逻辑

- **方案选择**：使用 `CABasicAnimation` 作用于 `transform.translation.x`。
    
- **成功原因**：
    
    - **独立性**：Layer 动画改变的是“呈现树 (Presentation Tree)”，而 Masonry 维护的是“模型树 (Model Tree)”。
        
    - **性能**：由 GPU 处理位移，不触发 CPU 的重新布局（Relayout），极其丝滑。
        
    - **时机**：即使系统重置了 Frame，Layer 动画依然会强行在绘制时加上偏移量。
        

---

## 📝 经验总结（Tips for your Note）

1. **约束是“契约”**：当你使用 Auto Layout 声明了“距离右边 15pt”时，它就是一个强力契约。普通的 `transform` 很难在布局期间违背它。
    
2. **动画冲突排查**：如果动画没效果，先做**“结果B实验”**（只设初始态）。如果初始态留不住，说明属性被其他地方重置了。
    
3. **willDisplayCell 的陷阱**：它是 Cell 刚要上场还没站稳的时刻，此时做 View 级操作很容易被系统的最后一次布局刷新给覆盖。
    
4. **底层思维**：当 UIView 层的动画无法解决冲突时，考虑往下一层走，去操作 **`CALayer`**。
    

---

**这套思维链路不仅适用于 TableView 动画，未来你遇到任何“代码执行了但 UI 没变化”的情况，都可以按照这个“View 属性 -> 布局约束 -> Layer 渲染”的顺序去排查。**

代码
```objc
#pragma mark**-delegate**

//当cell将要显示的时候调用

//最终方法，用Layer操作，而不是用动frame，可以避免约束带来的问题

- (**void**)tableView:(UITableView *)tableView willDisplayCell:(UITableViewCell *)cell forRowAtIndexPath:(NSIndexPath *)indexPath {

    // 1. 获取宽度

    CGFloat width = [UIScreen mainScreen].bounds.size.width;

  

    // 2. 直接对 Layer 进行平移（不影响 View 的 Transform）

    // 关键：不使用 UIView 动画，改用 Core Animation

    CABasicAnimation *animation = [CABasicAnimation animationWithKeyPath:@"transform.translation.x"];

    animation.fromValue = @(width); // 从屏幕右侧

    animation.toValue = @(0);      // 移动到原始位置

    animation.duration = 0.6;      // 时长

    animation.timingFunction = [CAMediaTimingFunction functionWithName:kCAMediaTimingFunctionEaseInEaseOut];

    // 给不同的行增加延迟

    animation.beginTime = CACurrentMediaTime() + (0.05 * indexPath.row);

    // 把动画加到 cell.layer 上

    [cell.layer addAnimation:animation forKey:@"slideIn"];

}

  

  

- (**void**)tableView:(UITableView *)tableView didSelectRowAtIndexPath:(NSIndexPath *)indexPath {

//     1. 立即取消选中状态，让灰色高亮闪一下就消失

    [tableView deselectRowAtIndexPath:indexPath animated:**YES**];

    // 2. 获取当前的 Cell 执行自定义动画

    LBWDiscoverTableViewCell *cell = [tableView cellForRowAtIndexPath:indexPath];

    // 3. 执行按压反馈动画

    [UIView animateWithDuration:0.1 animations:^{

        // 稍微缩小一点点 (0.95倍)

        cell.transform = CGAffineTransformMakeScale(0.95, 0.95);

    } completion:^(**BOOL** finished) {

        [UIView animateWithDuration:0.1 animations:^{

            // 恢复原状

            cell.transform = CGAffineTransformIdentity;

        } completion:^(**BOOL** finished) {

            // 4. 动画结束后再执行跳转逻辑，体验更好

            NSLog(@"点击了第 %ld 组，第 %ld 行", (**long**)indexPath.section, (**long**)indexPath.row);

            [**self** handleSelectionAtIndexPath:indexPath];

        }];

    }];

}

- (**void**)handleSelectionAtIndexPath:(NSIndexPath *)indexPath {

    // 这里处理你的跳转逻辑

    **if** (indexPath.section == 0) {

        NSLog(@"处理第 0 组的选择");

//         例如：推送一个新的控制器

//         UIViewController *testVC = [[UIViewController alloc] init];

//         testVC.view.backgroundColor = [UIColor whiteColor];

//         [self.navigationController pushViewController:testVC animated:YES];

    } **else** {

        NSLog(@"处理其他组的选择");

    }

}
```


| 分类               | KeyPath (字符串内容)                      | 作用                             |
| ---------------- | ------------------------------------ | ------------------------------ |
| 位移 (Translation) | transform.translation.x/y/z          | 水平/垂直/z轴的立体移动                  |
| 缩放 (Scale)       | transform.scale/.x/.y                | 整体/宽度/高度缩放                     |
| 旋转 (Rotation)    | `transform.rotation.z/.x`            | 平面旋转/绕x轴旋转                     |
| 外观 (Appearance)  | opacity/backgroundColor/cornerRadius | 透明度（对应 UIView 的 alpha）/背景颜色/圆角 |

或者可以使用animation.keyPath=NSStringFromSelector(@selector(方法名));
