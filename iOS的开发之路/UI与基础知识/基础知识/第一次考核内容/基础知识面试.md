### 一、视图生命周期（第15天）

  

#### 基础题

  

**题目1：** 请说明UIViewController的生命周期方法调用顺序，并说明每个方法的作用。

  

**参考答案：**

```

调用顺序：

loadView → viewDidLoad → viewWillAppear: → viewDidAppear:

→ viewWillDisappear: → viewDidDisappear: → dealloc

  

各方法作用：

- loadView: 创建视图层次结构（如果使用代码创建）

- viewDidLoad: 视图加载完成，只调用一次，适合初始化工作

- viewWillAppear: 视图即将显示，每次显示都会调用，适合刷新数据

- viewDidAppear: 视图已经显示，每次显示都会调用，适合开始网络请求

- viewWillDisappear: 视图即将消失，适合保存数据

- viewDidDisappear: 视图已经消失，适合清理资源

- dealloc: 对象销毁，移除通知和观察者

```

  

**评分要点：**

- 顺序正确（30%）

- 每个方法的作用说明准确（50%）

- 能说明调用时机和次数（20%）

**题目2：** 在viewDidLoad中开始网络请求和在viewDidAppear中开始网络请求有什么区别？哪种更好？

  

**参考答案：**

- **viewDidLoad**：只调用一次，适合加载基础数据，但会阻塞视图显示

- **viewDidAppear:**：每次显示都调用，适合刷新数据，视图已显示，用户体验更好

  

**推荐做法：**

- 基础数据：在viewDidLoad中加载

- 列表数据：在viewDidAppear中加载（避免阻塞显示）

- 非关键数据：在viewDidAppear中加载

  

**评分要点：**

- 理解两种方法的区别（40%）

- 能说明适用场景（40%）

- 给出最佳实践建议（20%）

#### 进阶题

  

**题目3：** 为什么viewDidLoad只调用一次，而viewWillAppear会调用多次？请从设计角度解释。

  

**参考答案：**

- **设计原因**：

1. 视图加载是一次性操作，所以viewDidLoad只调用一次

2. 视图显示是多次操作（push、pop、present、dismiss），所以viewWillAppear会多次调用

3. 这种设计允许在每次显示时刷新数据，而不需要重新加载视图

  

- **实际应用**：

- viewDidLoad：一次性初始化（设置UI、注册通知）

- viewWillAppear：每次显示时刷新（更新数据、显示导航栏）

  

**评分要点：**

- 理解设计原理（50%）

- 能说明实际应用场景（30%）

- 能举例说明（20%）

**题目13：** Cell重用机制的原理是什么？为什么要使用重用机制？

  

**参考答案：**

- **原理**：

1. UITableView维护一个Cell重用池

2. 当Cell滚出屏幕时，会被放入重用池

3. 需要新Cell时，优先从重用池获取

4. 如果重用池为空，才创建新Cell

  

- **好处**：

1. 减少内存占用

2. 提高滚动性能

3. 降低CPU消耗

**题目14：** `dequeueReusableCellWithIdentifier:` 和 `dequeueReusableCellWithIdentifier:forIndexPath:` 有什么区别？

  

**参考答案：**

- **dequeueReusableCellWithIdentifier:**：

- 如果重用池为空，返回nil

- 需要手动判断并创建Cell

- 需要先注册Cell

  

- **dequeueReusableCellWithIdentifier:forIndexPath:**：

- 如果重用池为空，会自动创建Cell（需要先注册）

- 不会返回nil

- 更安全，推荐使用

  

**代码示例：**

```objc

// 方式1：可能返回nil

UITableViewCell *cell = [tableView dequeueReusableCellWithIdentifier:@"Cell"];

if (!cell) {

cell = [[UITableViewCell alloc] initWithStyle:UITableViewCellStyleDefault reuseIdentifier:@"Cell"];

}

  

// 方式2：不会返回nil（推荐）

UITableViewCell *cell = [tableView dequeueReusableCellWithIdentifier:@"Cell" forIndexPath:indexPath];

```

  

**评分要点：**

- 区别说明准确（50%）

**参考答案：**

- **Hit-Test机制**：确定触摸事件发生在哪个视图上

- **关键方法**：

- `hitTest:withEvent:` - 查找响应视图

- `pointInside:withEvent:` - 判断点是否在视图内

```objc
- (UIView *)hitTest:(CGPoint)point withEvent:(UIEvent *)event {

// 扩大点击区域（上下左右各扩大20点）

CGRect expandedBounds = CGRectInset(self.bounds, -20, -20);

// 判断点是否在扩大后的区域内

if (CGRectContainsPoint(expandedBounds, point)) {

// 先检查子视图

for (UIView *subview in [self.subviews reverseObjectEnumerator]) {

CGPoint convertedPoint = [self convertPoint:point toView:subview];

UIView *hitView = [subview hitTest:convertedPoint withEvent:event];

if (hitView) {

return hitView;

}

}

// 如果没有子视图响应，返回自己

return self;

}

// 点不在扩大后的区域内，返回nil

return nil;

}

  

- (BOOL)pointInside:(CGPoint)point withEvent:(UIEvent *)event {

// 扩大点击区域

CGRect expandedBounds = CGRectInset(self.bounds, -20, -20);

return CGRectContainsPoint(expandedBounds, point);

}

```
