    ~~***本人浅薄的理解：** objc将以函数调用的内容转译为消息类型发送给编译器，函数调用的本质是传值，消息调用的本质是建立连接*~~
    **正确答案**：在objc中，我们使用函数本质上是在向编译器发送特殊的c函数调用，由于通常这个方法具有传输方和接收方，所以称之为消息发送；**本质区别** ：在于绑定时间：C语言是静态绑定，当你写下函数，编译器在编译阶段就已经知道了函数的内存地址了，而objc是动态绑定，你在写下[object method] 调用时，在编译后被转化为objc_msgSend(receriver,selector)，只有对象接收到消息，才回去寻找对应的代码；如果C的方法不存在会直接报错，如果objc的发送了没有实现的方法，oc不会立即报错
    
    - 考察点：理解消息机制的核心概念
2. **@property 中 strong、weak、copy 三个修饰符的区别和适用场景？**
    ~~**我的浅薄理解** ：Strong 适用于第一次出现的属性，背后没有指针指向他的强引用（ARC=0），weak适用于属性背后有指向他的强引用，比如在storyboard里面的属性，copy适用于那些必须放在外边又不想他被轻易修改的属性（数组等）~~

    weak：弱引用：不增加引用计数，对象销毁时指针自动置为nil，可以防止循环引用以及storyBoard下的UI控件
    copy：适用于数组，字典等不想被外部轻易修改的属性，本质是一种更安全的强引用

### **第二部分：内存管理 & 循环引用（第3-4天）**

#### **基础题（3个）**

6. **请解释MRC（Manual Reference Counting）的工作原理，retain/release/autorelease的作用？**
    ~~我的理解：没理解，完全不懂~~ 
    **标准答案** ：MRC就是手动释放内存，是早起iOS内存管理方式的一种，简单来说就是：**谁拥有对象，谁就负责释放它** 
    原理就是**引用计数** ，每一个oc对象内部有一个整型，记录着有多少指针指向它：
	- 当count>0,对象存活
	- count=0,对象会调用dealloc方法被销毁并释放内存
    MRC的三大方法：
	- retain-->保留你持有的对象-->计数器+1
	- release--> 释放你持有的对象-->计数器-1
	- autorelease-->延迟释放，放入“自动释放池”-->当前作用于结束时，计数器才-1
	为什么需要auto release？-->在方法内部release，对象直接就销毁了，最后传过来的就是个空指针，但不release就会内存泄露；
7. **ARC与MRC的主要区别是什么？ARC是如何避免手动管理的？** 
	~~ARC字如其名：自动计数，由机器自动决定是否释放内存，不用再手动dealloc~~ 
    **标准答案** ：MRC时程序员手动编写代码，而ARC时编译器自动插入代码；如何避免手动管理：在你写下代码的时候好，clang编译器就会分析对象的生命周期，在编译成二进制文件时在合适的地方为你自动插入retain，release，autorealese
    - 考察点：对现代内存管理的理解
9. **什么是循环引用？请给出一个实例代码，并说明解决方案。**
    ~~我的回答：循环引用就是一个属性被两个强引用指针所指，导致引用计数>1,导致无法被销毁，举例：~~
    ~~在storyboard里面建立了一个UIlabel，在属性里还用@propertproperty（sortong）强引用，解决办法：改成弱引用就好了~~
    **循环引用** 本质不是一个属性被两个指针指向，而是两个或多个对象互相持有对方的强引用，形成死循环
    真正的循环引用实例：Delegate 模式
这是 iOS 开发中最经典的循环引用场景。想象一下 Teacher（老师）和 Student（学生）的关系：

Objective-C

// Teacher.h
@property (nonatomic, strong) Student *student;

// Student.h
@property (nonatomic, strong) Teacher *teacher; // ⚠️ 这里是强引用
老师强引用了学生。

学生也强引用了老师。

当外界不再需要这对师生时，由于他们互相死死拽着对方，引用计数永远不会降为 0。
    
    - 考察点：最常见的内存泄漏问题

### **第三部分：集合类型 & Block（第5-9天）**

#### **基础题（2个）**

12. **NSArray和NSMutableArray的区别？什么时候使用哪一个？**
    ~~**我的回答** ：NSArray是一种不可变的只读数组，NSMutableArray是可变数组，NSArray主要用于存储固定的不能轻易更改的数据模型，需要对模型增删改查的时候好或者取用模型时用NSMutableArray造一个临时数组去用~~ 
    **标准答案** ：
	1. 核心区别是**不可变性** ；    
		1. NSArray一旦创建，内部的元素数量和顺序就不能改变
		2. NSMutableArray：是NSArray的子类，它在内存中保留了一个缓冲区，允许你动态的addobject，removeobject或者是insertObject：atIndex
	2. 什么时候用哪一个？
		1. NSArray：用于对外暴露的属性，比如在.h文件声明属性时，即使内部可变，对外声明也用NSarray，防止其他类无意中修改了你的数据，符合封装原则；同时NSArray不需要管理动态缓存区，查找效率略高于NSMutableArray，且内存占用更小
		2. NSMutableArray：主要用于**数据聚合** ：从数据库中分批读取数据，或者在循环中动态构建列表；**UI交互** ：当用户在界面上滑动删除某一行或者拖拽排序的时候，必须使用可变数组
    - 考察点：集合类型的选择
14. **什么是Block？简述其语法和作用？**
    ~~我的回答：就是区别于传统delegate的一种代理方式，把消息封装成块，可以随处调用~~
	**标准答案** ：
	1. **Block是什么** ：Block顾名思义就是闭包，本质就是一个”匿名函数“加上上下文；可以吧Block比喻成背着书包的小人：小人本身是一段代码逻辑；而书包里装着的是Block**定义的那一刻** ，周围环境里面的变量，即使Block离开的原来的地方，他依然带着这些变量可以随处使用
	2. **语法**：
		1. 声明并定义：
			```objc
			//返回值类型（^Block名称)(参数类型)=^(参数列表){代码块}；
			void (^myBlock)(NSString *)=^(NSString *name){
			NSLog(@"你好，%@",name);
			};
			```
		2. 作为方法的参数：
			```objc
			-(void)doSomething:(Void(^)(int result))completion{
			//模拟一些工作
			completion(100);//任务结束，调用Block
			}
			```
		3. typedef：
			```objc
			typedef void(^CompletionHandler)(BOOL success);
			//之后就可以用NSStirng一样用这个类型了；
			@property(nonatomic,copy)CompletionHandler onFinished;
			```
	3. **核心功能** ：就是**逻辑的传递** ，传递的不是数据，而是动作。那为什么用它而不用Delegate
		1. 高聚合（所见即所得）
			1. Delegate：你发起网络请求需要到代理方法中处理结果，代码散乱
			2. Block：在你发起请求的过程中，直接在后面写成功了怎么办，失败了怎么办，逻辑连贯
		2.  Callback:可以在动画执行完或者网络请求完进行回调

### **2. 易错点总结**

|weak指针|"weak引用被释放后会崩溃"|weak指针置为nil，安全|
