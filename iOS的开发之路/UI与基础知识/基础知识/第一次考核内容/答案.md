4. **如果一个类同时采纳多个协议，且协议之间有同名方法，会发生什么？**
    
    - 考察点：协议冲突处理、问题排查能力
    
    **标准答案**：
    - **编译阶段**：编译器会允许这样的声明。因为协议只是定义接口，不提供实现。在 `.h` 文件中声明类采纳多个协议是完全合法的。
    - **实现阶段**：在 `.m` 文件中实现方法时，编译器不会产生冲突。因为每个协议中的同名方法视为同一个方法，你只需要实现一次即可。
    - **运行时**：调用该方法时，消息发送机制会找到实现，顺利执行。
    
    **代码示例**：
    ```objc
    @protocol ProtocolA <NSObject>
    - (void)doSomething;
    @end
    
    @protocol ProtocolB <NSObject>
    - (void)doSomething;  // 同名方法
    @end
    
    @interface MyClass : NSObject <ProtocolA, ProtocolB>
    @end
    
    @implementation MyClass
    - (void)doSomething {  // 实现一次即可满足两个协议
        NSLog(@"Doing something");
    }
    @end
    ```
    
    **注意**：如果协议中的方法签名不同（参数、返回值不同），会产生编译警告。

5. **Category能否添加成员变量？为什么？如何变通解决？**
    
    - 考察点：深层理解Category的局限和解决方案
    
    **标准答案**：
    - **不能直接添加成员变量**。原因：
        - Category 的本质是在编译时为类添加方法，作用于已经编译的类
        - 类的内存布局（成员变量的偏移量）在编译时已经确定，运行时无法改变
        - 如果强行添加成员变量，会破坏类的内存结构，导致崩溃
    
    - **变通解决方案**（3种）：
        1. **使用关联对象（Associated Objects）**：
            ```objc
            #import <objc/runtime.h>
            
            @interface NSString (MyCategory)
            @property (nonatomic, strong) NSString *customValue;
            @end
            
            @implementation NSString (MyCategory)
            
            - (void)setCustomValue:(NSString *)customValue {
                objc_setAssociatedObject(self, @"customValue", customValue, OBJC_ASSOCIATION_STRONG);
            }
            
            - (NSString *)customValue {
                return objc_getAssociatedObject(self, @"customValue");
            }
            @end
            ```
        
        2. **使用继承**：如果需要状态，创建子类而不是 Category
            ```objc
            @interface MyString : NSString {
                NSString *_customValue;  // 可以添加成员变量
            }
            @end
            ```
        
        3. **在容器中存储**：用字典或数组关联数据
            ```objc
            NSMutableDictionary *storage = @{}.mutableCopy;
            [storage setObject:value forKey:@"key"];
            ```

6. **请解释MRC（Manual Reference Counting）的工作原理，retain/release/autorelease的作用？**
    ~~我的理解：没理解，完全不懂~~ 
    **标准答案** ：MRC就是手动释放内存，是早起iOS内存管理方式的一种，简单来说就是：**谁拥有对象，谁就负责释放它** 
    原理就是**引用计数** ，每一个oc对象内部有一个整型，记录着有多少指针指向它：
    - 当count>0,对象存活
    - count=0,对象会调用dealloc方法被销毁并释放内存
    MRC的三大方法：
    - retain-->保留你持有的对象-->计数器+1
    - release--> 释放你持有的对象-->计数器-1
    - autorelease-->延迟释放，放入"自动释放池"-->当前作用于结束时，计数器才-1
    为什么需要auto release？-->在方法内部release，对象直接就销毁了，最后传过来的就是个空指针，但不release就会内存泄露；
    
    - 考察点：引用计数的基本原理

7. **ARC与MRC的主要区别是什么？ARC是如何避免手动管理的？** 
    ~~ARC字如其名：自动计数，由机器自动决定是否释放内存，不用再手动dealloc~~ 
    **标准答案** ：MRC时程序员手动编写代码，而ARC时编译器自动插入代码；如何避免手动管理：在你写下代码的时候好，clang编译器就会分析对象的生命周期，在编译成二进制文件时在合适的地方为你自动插入retain，release，autorealese

8. **什么是循环引用？请给出一个实例代码，并说明解决方案。**
    ~~我的回答：循环引用就是一个属性被两个强引用指针所指，导致引用计数>1,导致无法被销毁，举例：~~
    ~~在storyboard里面建立了一个UIlabel，在属性里还用@propertproperty（sortong）强引用，解决办法：改成弱引用就好了~~
    **循环引用** 本质不是一个属性被两个指针指向，而是两个或多个对象互相持有对方的强引用，形成死循环
    真正的循环引用实例：Delegate 模式
    这是 iOS 开发中最经典的循环引用场景。想象一下 Teacher（老师）和 Student（学生）的关系：
    
    ```objc
    // Teacher.h

#### **深入题（3个）**

9. **解释 weak 修饰符的工作原理。为什么weak引用的对象释放后，指针自动置为nil？**
    
    - 考察点：Runtime底层机制、weak表的实现
    
    **标准答案**：
    - **weak 的工作原理**：
        1. **Weak Hash Table（弱引用表）**：Runtime 维护一个全局的 weak 表（哈希表），记录所有 weak 引用
        2. **注册过程**：当你声明 `@property (nonatomic, weak) MyClass *obj;` 时，编译器生成的 setter 会调用 `objc_storeWeak()` 将该引用注册到 weak 表中
        3. **查询**：对象的 isa 指针中有一个标志位，表示该对象是否被 weak 引用
    
    - **自动置为 nil 的机制**：
        1. 当对象的引用计数减为 0 时，触发 dealloc
        2. dealloc 过程中，调用 `clearDeallocating()` 方法
        3. 该方法查找 weak 表中所有指向该对象的 weak 指针
        4. 将这些指针**逐一置为 nil**
        5. 从 weak 表中删除该对象的记录
    
    **代码演示**：
    ```objc
    @interface MyClass : NSObject
    @end
    
    MyClass *strongRef = [[MyClass alloc] init];
    
    __weak MyClass *weakRef = strongRef;
    
    NSLog(@"%@", weakRef);  // 输出对象地址
    
    strongRef = nil;  // 引用计数降为0，触发dealloc
    
    NSLog(@"%@", weakRef);  // 输出 (null) - 已自动置为nil
    ```
    
    **优势**：
    - 避免循环引用
    - 避免悬空指针导致的崩溃
    - 使 weak 指针比 strong 指针更安全

10. **AutoreleasePool的工作原理是什么？什么时候应该手动创建AutoreleasePool？**
    
    - 考察点：自动释放池的使用场景
    
    **标准答案**：
    - **AutoreleasePool 的工作原理**：
        1. **栈结构**：AutoreleasePool 是一个栈结构，每个 pool 是一个节点
        2. **对象存储**：调用 `autorelease` 的对象被加入最近的 pool 中
        3. **FIFO 释放**：当 pool 销毁时，对所有存储的对象发送 `release` 消息
        4. **线程关联**：每个线程都有独立的 AutoreleasePool 栈
    
    - **系统自动创建的时机**：
        - 主线程：Runloop 的每个循环开始时创建 pool，结束时销毁
        - 子线程：需要手动创建
    
    - **何时手动创建 AutoreleasePool**：
        1. **大量临时对象**：循环中产生大量 autoreleased 对象
            ```objc
            @autoreleasepool {
                for (int i = 0; i < 100000; i++) {
                    NSString *temp = [NSString stringWithFormat:@"%d", i];  // 自动释放
                    // 处理 temp
                }  // 循环结束，pool 销毁，temp 被释放，内存立即回收
            }
            ```
        
        2. **子线程操作**：子线程中产生 autoreleased 对象
            ```objc
            - (void)threadWork {
                @autoreleasepool {
                    // 在子线程中做任何可能产生 autoreleased 对象的操作
                    NSData *data = [NSData dataWithContentsOfFile:@"..."];
                    // ...
                }  // 离开线程前，pool 销毁，及时释放内存
            }
            ```
        
        3. **处理大量网络数据**：批量下载或处理文件
        4. **定时器任务**：长时间运行的任务中

11. **在Block中捕获self时，为什么会形成循环引用？如何使用__weak self来解决？**
    
    - 考察点：Block的捕获机制、内存管理最佳实践
    
    **标准答案**：
    - **为什么会形成循环引用**：
        1. Block 的捕获机制：当 block 访问外部变量时，block 会**强引用**该变量（包括 self）
        2. 通常 self 持有 block（比如作为属性或 completion handler 参数）
        3. 形成死循环：self → block，block → self，引用计数永不为 0
    
    - **具体场景**：
        ```objc
        @interface ViewController : UIViewController
        @property (nonatomic, copy) void (^myBlock)(void);
        @end
        
        @implementation ViewController
        - (void)viewDidLoad {
            [super viewDidLoad];
            
            // ⚠️ 危险：block 强引用 self，self 也强引用 block
            self.myBlock = ^{
                NSLog(@"%@", self);  // block 捕获 self
            };
        }
        @end
        ```
    
    - **使用 __weak self 解决**：
        ```objc
        - (void)viewDidLoad {
            [super viewDidLoad];
            
            __weak ViewController *weakSelf = self;
            
            self.myBlock = ^{
                // 此时 block 只持有 weakSelf（弱引用），不增加引用计数
                NSLog(@"%@", weakSelf);
            };
        }
        ```
    
    - **进阶：__weak 和 __strong 结合**（防止执行时 self 被释放）：
        ```objc
        __weak ViewController *weakSelf = self;
        
        self.myBlock = ^{
            __strong ViewController *strongSelf = weakSelf;
            if (strongSelf) {
                // 在 block 执行期间保持 self 活跃
                [strongSelf doSomething];
            }
        };
        ```

#### **深入题（4个）**

14. **深浅拷贝的区别是什么？如何自定义对象的copy方法？**
    
    - 考察点：NSCopying协议的实现、内存效率
    
    **标准答案**：
    - **深浅拷贝的区别**：
        1. **浅拷贝（Shallow Copy）**：
            - 只复制指针，不复制指针指向的内容
            - 新对象和原对象共享同一块内存
            - 修改一方会影响另一方
            - 内存占用少，效率高
        
        2. **深拷贝（Deep Copy）**：
            - 复制指针和指针指向的内容
            - 创建完全独立的对象副本
            - 修改一方不影响另一方
            - 内存占用多，效率稍低
    
    **集合类型的拷贝行为**：
    ```objc
    // 浅拷贝示例
    NSArray *array1 = @[@"a", @"b"];
    NSArray *array2 = [array1 copy];  // 复制数组结构，但元素还是同一个对象
    
    // 深拷贝示例（嵌套对象）
    NSArray *array3 = [[NSArray alloc] initWithArray:array1 copyItems:YES];
    ```
    
    - **自定义对象的 copy 方法**（实现 NSCopying 协议）：
        ```objc
        @interface Person : NSObject <NSCopying>
        @property (nonatomic, strong) NSString *name;
        @property (nonatomic, assign) NSInteger age;
        @end
        
        @implementation Person
        
        - (id)copyWithZone:(NSZone *)zone {
            // 创建新对象（zone 是内存分配的区域，通常传 NULL）
            Person *copy = [[Person allocWithZone:zone] init];
            
            // 复制属性值（深拷贝 NSString）
            copy.name = [self.name copy];  // NSString 也要拷贝
            copy.age = self.age;
            
            return copy;
        }
        
        @end
        ```
    
    - **何时使用 copy**：
        ```objc
        @property (nonatomic, copy) NSString *name;  // NSString、NSArray、NSDictionary 等
        @property (nonatomic, copy) NSArray *items;
        ```

            - 你可能不小心将 NSMutableString 对象放入集合
            ```objc
            NSMutableString *mutableStr = [NSMutableString stringWithString:@"hello"];
            NSArray *array = @[mutableStr];
            
            [mutableStr appendString:@" world"];  // 修改原字符串
            // 此时数组中的字符串也被修改了！
            ```
        
        2. **使用 copy 的好处**：
            - 当加入可变对象时，自动转换为不可变副本
            - 保护集合内的数据不被外部修改
    
    - **代码示例**：
        ```objc
        @interface Configuration : NSObject
        @property (nonatomic, copy) NSString *appName;      // ✅ 使用 copy
        @property (nonatomic, strong) NSNumber *version;    // ⚠️ 容易踩坑
        @end
        
        // 更安全的做法
        @interface Configuration : NSObject
        @property (nonatomic, copy) NSString *appName;
        @property (nonatomic, copy) NSNumber *version;      // ✅ 也用 copy
        @end
        ```
    
    - **NSArray/NSDictionary 的属性声明**：
        ```objc
        // ❌ 不安全
        @property (nonatomic, strong) NSArray *items;
        
        // ✅ 安全
        @property (nonatomic, copy) NSArray *items;
        
        // 原因：外部可能传入 NSMutableArray
        NSMutableArray *mutArray = [@[@"a", @"b"] mutableCopy];
        config.items = mutArray;  // 如果用 strong，mutArray 被修改会影响 config.items
        [mutArray addObject:@"c"];
        ```

16. **请解释Block的三种形式（栈Block、堆Block、全局Block），它们有什么区别？**
    
    - 考察点：Block内存管理、捕获变量机制
    
    **标准答案**：
    - **全局Block（Global Block）**：
        - **定义**：不捕获任何外部变量的 block
        - **存储位置**：`.data` 段（全局数据区）
        - **生命周期**：程序启动至结束
        - **捕获变量**：不捕获
        ```objc
        void (^globalBlock)(void) = ^{
            NSLog(@"This is a global block");  // 不访问外部变量
        };
        ```
    
    - **栈Block（Stack Block）**：
        - **定义**：捕获外部变量的 block
        - **存储位置**：栈内存
        - **生命周期**：所在作用域结束时销毁
        - **问题**：如果被传递到作用域外，会变成野指针
        ```objc
        int x = 10;
        void (^stackBlock)(void) = ^{
            NSLog(@"%d", x);  // 捕获 x
        };
        // 离开作用域，stackBlock 可能无效
        ```
    
    - **堆Block（Heap Block）**：
        - **定义**：被 copy 到堆上的 block
        - **存储位置**：堆内存
        - **生命周期**：由内存管理器控制
        - **获得方式**：对 stack block 发送 copy 消息
        ```objc
        int x = 10;
        void (^heapBlock)(void) = [^{
            NSLog(@"%d", x);
        } copy];  // 显式复制到堆上
        // 或者使用属性声明时自动转为堆Block
        @property (nonatomic, copy) void(^myBlock)(void);
        ```
    
    - **三者对比表**：
        | 特性 | 全局Block | 栈Block | 堆Block |
        |------|---------|--------|--------|
        | 存储位置 | .data段 | 栈 | 堆 |
        | 捕获变量 | 否 | 是 | 是 |
        | 生命周期 | 整个程序 | 作用域内 | 手动管理 |
        | 传递安全性 | ✅ 安全 | ❌ 危险 | ✅ 安全 |
        | 是否需要 copy | 否 | 是 | 否 |

17. **Block中的__block修饰符有什么作用？为什么需要它？**
    
    - 考察点：Block变量捕获机制
    
    **标准答案**：
    - **Block 的变量捕获机制**：
        1. **默认捕获（值捕获）**：
            ```objc
            int x = 10;
            void (^myBlock)(void) = ^{
                NSLog(@"%d", x);  // 捕获的是 x 的值（10）
            };
            x = 20;
            myBlock();  // 输出仍然是 10，不是 20
            ```
            - Block 捕获的是**执行时 x 的值**
            - 之后修改 x，block 内部看到的仍是旧值
        
        2. **对象捕获（引用捕获）**：
            ```objc
            NSMutableArray *array = [@[@1, @2] mutableCopy];
            void (^myBlock)(void) = ^{
                [array addObject:@3];  // 能修改数组
            };
            myBlock();
            // array 现在是 [@1, @2, @3]
            ```
            - Block 捕获的是**指针本身**
            - 可以通过指针修改对象
            - 但不能修改指针的指向
    
    - **__block 的作用**：
        ```objc
        __block int x = 10;
        void (^myBlock)(void) = ^{
            x = 20;  // ✅ 可以修改 x
        };
        myBlock();
        NSLog(@"%d", x);  // 输出 20
        ```
        - 允许 block 修改捕获的**值类型变量**
        - 使变量从"值捕获"变为"引用捕获"
    
    - **为什么需要 __block**：
        ```objc
        int counter = 0;
        
        // ❌ 没有 __block，无法修改 counter
        void (^increment1)(void) = ^{
            // counter++;  // 编译错误
        };
        
        // ✅ 有 __block，可以修改 counter
        __block int counter2 = 0;
        void (^increment2)(void) = ^{
            counter2++;  // ✅ OK
        };
        ```
    
    - **常见场景**：
        ```objc
        __block NSInteger count = 0;
        
        [UIView animateWithDuration:0.3 animations:^{
            // 在 block 中修改 count
            count++;
        }];
        ```

19. **解释一下动态方法解析（Dynamic Method Resolution），什么时候使用？**
    
    - 考察点：消息转发流程的第一步
    
    **标准答案**：
    - **什么是动态方法解析**：
        - 当对象接收到一条**未实现的消息**时，Runtime 会调用 `+resolveInstanceMethod:` 或 `+resolveClassMethod:` 
        - 这给了类一个机会在**运行时动态添加方法实现**
        - 是消息转发的**第一阶段**
    
    - **工作流程**：
        1. `[obj unknownMethod]` 被调用
        2. Runtime 在 obj 的类中查找方法，未找到
        3. 调用 `+resolveInstanceMethod:@selector(unknownMethod)`
        4. 如果返回 YES，说明方法已添加，重新查询并执行
        5. 如果返回 NO，进入第二阶段（快速转发）
    
    - **代码实现**：
        ```objc
        @interface MyClass : NSObject
        @end
        
        @implementation MyClass
        
        // 动态处理实例方法
        + (BOOL)resolveInstanceMethod:(SEL)sel {
            if (sel == @selector(dynamicMethod:)) {
                // 添加方法实现
                class_addMethod([self class],
                               sel,
                               (IMP)dynamicMethodImp,
                               "v@:@");  // 返回值、self、_cmd、参数类型
                return YES;
            }
            return [super resolveInstanceMethod:sel];
        }
        
        // 方法的实现
        void dynamicMethodImp(id self, SEL _cmd, id parameter) {
            NSLog(@"Dynamic method called with: %@", parameter);
        }
        
        @end
        ```
    
    - **何时使用**：
        1. **懒加载方法**：只在需要时才添加方法
        2. **热修复**：在运行时修补 bug
        3. **动态代理**：为多个对象动态生成方法
        4. **性能优化**：延迟加载不常用的方法

20. **请详细描述Objective-C中方法调用的完整流程（从消息发送到执行）。**
    
    - 考察点：消息转发的三个阶段
    
    **标准答案**：
    
    方法调用的完整过程分为三个阶段：
    
    - **第一阶段：动态方法解析（Dynamic Method Resolution）**
        1. 编译器将 `[object method]` 转换为 `objc_msgSend(object, @selector(method))`
        2. Runtime 在对象的类中查找 SEL 对应的 IMP（方法实现）
        3. 如果找到，直接调用并返回
        4. 如果未找到，调用 `+resolveInstanceMethod:` 或 `+resolveClassMethod:`
        5. 如果该方法返回 YES，重新查询（允许动态添加方法）
        6. 如果返回 NO，进入第二阶段
    
    - **第二阶段：快速转发（Fast Forwarding）**
        1. 调用 `-forwardingTargetForSelector:`
        2. 如果返回一个能处理该 selector 的对象，将消息转发给它
        3. 如果返回 nil，进入第三阶段
        
        ```objc
        - (id)forwardingTargetForSelector:(SEL)aSelector {
            if (aSelector == @selector(unknownMethod)) {
                return self.otherObject;  // 将消息转发给其他对象
            }
            return [super forwardingTargetForSelector:aSelector];
        }
        ```
    
    - **第三阶段：标准转发（Normal Forwarding）**
        1. 调用 `-methodSignatureForSelector:` 获取方法签名
        2. 根据方法签名创建 NSInvocation 对象
        3. 调用 `-forwardInvocation:` 处理 invocation
        4. 如果没有实现这个方法，抛出 unrecognized selector 异常
        
        ```objc
        - (NSMethodSignature *)methodSignatureForSelector:(SEL)aSelector {
            if (aSelector == @selector(unknownMethod:)) {
                return [NSMethodSignature signatureWithObjCTypes:"v@:@"];
            }
            return [super methodSignatureForSelector:aSelector];
        }
        
        - (void)forwardInvocation:(NSInvocation *)anInvocation {
            if (anInvocation.selector == @selector(unknownMethod:)) {
                // 手动处理或转发给其他对象
                [self.delegate forwardInvocation:anInvocation];
            } else {
                [super forwardInvocation:anInvocation];
            }
        }
        ```
    
    - **完整流程图**：
        ```
        [object method]
           ↓
        objc_msgSend(object, selector)
           ↓
        在类的方法列表中查找
        ├─ 找到 IMP → 执行并返回
        └─ 未找到 → 第一阶段：动态方法解析
               ↓
        +resolveInstanceMethod:
        ├─ 返回 YES → 重新查询方法列表
        └─ 返回 NO → 第二阶段：快速转发
               ↓
        -forwardingTargetForSelector:
        ├─ 返回对象 → 转发消息给该对象
        └─ 返回 nil → 第三阶段：标准转发
               ↓
        -methodSignatureForSelector:
        ├─ 返回签名 → 创建 NSInvocation
        │       ↓
        │   -forwardInvocation:
        │       ↓
        │     处理或再次转发
        └─ 返回 nil → 抛异常：unrecognized selector
        ```

21. **什么是Method Swizzling？有什么注意事项？请给出一个实际应用场景。**
    
    - 考察点：高级特性理解、工程实践
    
    **标准答案**：
    - **什么是 Method Swizzling**：
        - 在**运行时**交换两个方法的实现（IMP）
        - 通过修改类的方法表，将原方法指向新实现，新方法指向原实现
        - 是一种强大但危险的技术
    
    - **基本实现**：
        ```objc
        #import <objc/runtime.h>
        
        @implementation UIViewController (Tracking)
        
        + (void)load {
            // +load 保证类加载时执行一次
            static dispatch_once_t onceToken;
            dispatch_once(&onceToken, ^{
                // 交换 viewWillAppear: 和 custom_viewWillAppear: 的实现
                Method originalMethod = class_getInstanceMethod(self, @selector(viewWillAppear:));
                Method swizzledMethod = class_getInstanceMethod(self, @selector(custom_viewWillAppear:));
                
                method_exchangeImplementations(originalMethod, swizzledMethod);
            });
        }
        
        // 新的实现（会被命名为 viewWillAppear:）
        - (void)custom_viewWillAppear:(BOOL)animated {
            [self custom_viewWillAppear:animated];  // 调用原实现
            NSLog(@"ViewController appeared");  // 添加新逻辑
        }
        
        @end
        ```
    
    - **注意事项**：
        1. **只在 +load 中执行**：避免多次交换
        2. **使用 dispatch_once**：保证线程安全和单次执行
        3. **要调用原方法**：否则会破坏原功能
        4. **避免滥用**：会使代码难以追踪和调试
        5. **谨慎继承关系**：子类可能需要单独处理
        6. **注意方法签名**：确保两个方法签名相同
    
    - **实际应用场景**：
        1. **埋点追踪**：
            ```objc
            - (void)custom_viewDidLoad {
                [self custom_viewDidLoad];  // 调用原 viewDidLoad
                [Tracker trackPageView:NSStringFromClass([self class])];
            }
            ```
        
        2. **性能监测**：
            ```objc
            + (void)load {
                method_exchangeImplementations(
                    class_getInstanceMethod(self, @selector(viewWillAppear:)),
                    class_getInstanceMethod(self, @selector(tracked_viewWillAppear:))
                );
            }
            
            - (void)tracked_viewWillAppear:(BOOL)animated {
                CFTimeInterval start = CACurrentMediaTime();
                [self tracked_viewWillAppear:animated];
                CFTimeInterval duration = CACurrentMediaTime() - start;
                NSLog(@"viewWillAppear 耗时: %.3f ms", duration * 1000);
            }
            ```
        
        3. **修复系统 Bug**（hot fix）
        4. **统一添加功能**：如日志、权限检查等

23. **能否通过Runtime实现方法的AOP（面向切面编程）？如何实现？**
    
    - 考察点：高级应用、系统设计思维
    
    **标准答案**：
    - **什么是 AOP（Aspect-Oriented Programming）**：
        - 在不修改原代码的情况下，为方法添加"切面"逻辑
        - 常用于：日志、权限检查、性能监测、缓存等横切关注点
    
    - **实现方式 1：Method Swizzling**
        ```objc
        @implementation NSString (AOP)
        
        + (void)load {
            static dispatch_once_t onceToken;
            dispatch_once(&onceToken, ^{
                Method originalMethod = class_getInstanceMethod(self, @selector(length));
                Method aopMethod = class_getInstanceMethod(self, @selector(aop_length));
                method_exchangeImplementations(originalMethod, aopMethod);
            });
        }
        
        - (NSUInteger)aop_length {
            NSLog(@"Before: getting string length");
            NSUInteger length = [self aop_length];  // 原方法
            NSLog(@"After: length = %lu", length);
            return length;
        }
        
        @end
        ```
    
    - **实现方式 2：NSInvocation（更灵活）**
        ```objc
        @interface AspectProxy : NSObject
        @property (nonatomic, strong) id target;
        @property (nonatomic, copy) void(^before)(NSInvocation *);
        @property (nonatomic, copy) void(^after)(NSInvocation *);
        @end
        
        @implementation AspectProxy
        
        - (NSMethodSignature *)methodSignatureForSelector:(SEL)sel {
            return [self.target methodSignatureForSelector:sel];
        }
        
        - (void)forwardInvocation:(NSInvocation *)invocation {
            if (self.before) {
                self.before(invocation);
            }
            
            [invocation invokeWithTarget:self.target];
            
            if (self.after) {
                self.after(invocation);
            }
        }
        
        @end
        
        // 使用
        AspectProxy *proxy = [[AspectProxy alloc] init];
        proxy.target = myObject;
        
        proxy.before = ^(NSInvocation *invocation) {
            NSLog(@"Method %@ called", NSStringFromSelector(invocation.selector));
        };
        
        proxy.after = ^(NSInvocation *invocation) {
            NSLog(@"Method %@ finished", NSStringFromSelector(invocation.selector));
        };
        
        [proxy someMethod];
        ```
    
    - **实现方式 3：Hook 所有方法**
        ```objc
        @implementation UIViewController (GlobalAOP)
        
        + (void)load {
            static dispatch_once_t onceToken;
            dispatch_once(&onceToken, ^{
                [self hookAllMethods];
            });
        }
        
        + (void)hookAllMethods {
            unsigned int methodCount = 0;
            Method *methods = class_copyMethodList(self, &methodCount);
            
            for (unsigned int i = 0; i < methodCount; i++) {
                Method method = methods[i];
                SEL selector = method_getName(method);
                const char *typeEncoding = method_getTypeEncoding(method);
                
                IMP originalImp = method_getImplementation(method);
                
                IMP newImp = imp_implementationWithBlock(^(id selfValue) {
                    NSLog(@"Before: %@", NSStringFromSelector(selector));
                    ((void (*)(id, SEL))originalImp)(selfValue, selector);
                    NSLog(@"After: %@", NSStringFromSelector(selector));
                });
                
                method_setImplementation(method, newImp);
            }
            
            free(methods);
        }
        
        @end
        ```
    
    - **实际应用场景**：
        1. **性能监测**：统计方法执行时间
        2. **日志记录**：记录所有方法调用
        3. **权限检查**：在执行敏感操作前检查权限
        4. **缓存**：自动缓存方法结果
        5. **错误处理**：统一捕获和处理异常

24. **什么是KVC（Key-Value Coding）？setValue:forKey:的实现原理？**
    
    - 考察点：KVC的工作机制
    
    **标准答案**：
    - **什么是 KVC**：
        - Key-Value Coding，一种通过键值对间接访问对象属性的机制
        - 是 Objective-C 动态特性的重要体现
        - 允许通过字符串名称访问和修改对象属性，无需知道编译时的类型
    
    - **基本用法**：
        ```objc
        @interface Person : NSObject
        @property (nonatomic, copy) NSString *name;
        @property (nonatomic, assign) NSInteger age;
        @end
        
        Person *person = [[Person alloc] init];
        
        // 设置值
        [person setValue:@"Alice" forKey:@"name"];
        [person setValue:@25 forKey:@"age"];
        
        // 获取值
        NSString *name = [person valueForKey:@"name"];
        NSInteger age = [[person valueForKey:@"age"] integerValue];
        ```
    
    - **setValue:forKey: 的实现原理**：
        当执行 `[obj setValue:value forKey:@"propertyName"]` 时，Runtime 按以下顺序查找：
        
        1. **第一步**：查找 setter 方法
            - 按照 KVC 命名规范查找 `setPropertyName:` 方法
            - 如果找到，调用该方法设置值
        
        2. **第二步**：检查 `_propertyName` 成员变量
            - 如果没有找到 setter，检查是否存在 `_propertyName` 的实例变量
            - 如果存在，直接赋值
        
        3. **第三步**：检查 `propertyName` 成员变量
            - 如果还没找到，检查 `propertyName` 成员变量
            - 如果存在，直接赋值
        
        4. **第四步**：调用 `setValue:forUndefinedKey:`
            - 如果以上都失败，调用这个方法处理
            - 默认抛出异常：NSUndefinedKeyException
    
    - **搜索顺序的代码演示**：
        ```objc
        @interface Person : NSObject {
            NSString *_name;  // 优先级：1
            NSString *name;   // 优先级：2
        }
        @property (nonatomic, copy) NSString *name;
        @end
        
        // 调用顺序：setName: -> _name -> name -> 异常
        ```
    
    - **valueForKey: 的查询顺序**（反向）：
        1. getter 方法（`propertyName`、`isPropertyName` for BOOL）
        2. `_propertyName` 成员变量
        3. `propertyName` 成员变量
        4. 调用 `valueForUndefinedKey:`

25. **什么是KVO（Key-Value Observing）？如何观察属性变化？**
    
    - 考察点：KVO的基本使用
    
    **标准答案**：
    - **什么是 KVO**：
        - Key-Value Observing，一种观察对象属性值变化的机制
        - 基于 Runtime 的动态类生成和消息转发
        - 是典型的观察者模式实现
    
    - **基本使用**：
        ```objc
        @interface Person : NSObject
        @property (nonatomic, assign) NSInteger age;
        @end
        
        @interface ViewController : UIViewController
        @end
        
        @implementation ViewController
        
        - (void)viewDidLoad {
            [super viewDidLoad];
            
            Person *person = [[Person alloc] init];
            
            // 1. 添加观察者
            [person addObserver:self
                    forKeyPath:@"age"
                       options:NSKeyValueObservingOptionNew | NSKeyValueObservingOptionOld
                       context:NULL];
            
            // 2. 修改属性值
            person.age = 25;  // 会触发观察回调
            
            // 3. 在 dealloc 中移除观察者
            [person removeObserver:self forKeyPath:@"age"];
        }
        
        // 4. 实现观察回调
        - (void)observeValueForKeyPath:(NSString *)keyPath
                              ofObject:(id)object
                                change:(NSDictionary<NSKeyValueChangeKey,id> *)change
                               context:(void *)context {
            if ([keyPath isEqualToString:@"age"]) {
                NSNumber *oldValue = change[NSKeyValueChangeOldKey];
                NSNumber *newValue = change[NSKeyValueChangeNewKey];
                NSLog(@"Age changed from %@ to %@", oldValue, newValue);
            }
        }
        
        @end
        ```
    
    - **options 参数详解**：
        ```objc
        NSKeyValueObservingOptionNew      // 通知时发送新值
        NSKeyValueObservingOptionOld      // 通知时发送旧值
        NSKeyValueObservingOptionInitial  // 注册后立即发送通知
        NSKeyValueObservingOptionPrior    // 修改前和修改后各通知一次
        ```
    
    - **change 字典的内容**：
        ```objc
        change[NSKeyValueChangeKindKey]     // 变化类型 (@"setting", @"insertion", etc.)
        change[NSKeyValueChangeNewKey]      // 新值（如果指定了 NSKeyValueObservingOptionNew）
        change[NSKeyValueChangeOldKey]      // 旧值（如果指定了 NSKeyValueObservingOptionOld）
        change[NSKeyValueChangeIndexesKey]  // 集合变化时的索引## 📋
