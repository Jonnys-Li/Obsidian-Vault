
# 🧠 Objective-C 开发基础核心考核大纲

## 一、 语法基础与架构设计

### 1. 消息发送 (Messaging)

- **本质**：Objective-C 的方法调用在编译后会被转化为 `objc_msgSend(receiver, selector)`。
    
- **与 C 语言的区别**：C 语言是静态绑定，编译时即确定函数地址；Objective-C 是动态绑定，在运行时才寻找代码实现。
    
- **安全特性**：若方法不存在，C 语言会直接报错，而 Objective-C 会进入消息转发流程，不会立即报错。
    

### 2. 协议 (Protocol) 与 分类 (Category)

- **Protocol (定义标准)**：
    
    - 仅声明方法而不实现，不关心具体实现对象。
        
    - 实例：`UITableViewDataSource` 要求实现者提供行数、Cell 等信息。
        
- **Category (功能扩展)**：
    
    - 为既有类添加新方法并提供具体实现。
        
    - 局限性：不能直接添加成员变量，因为类内存布局在编译时已确定。
        
    - 变通方案：使用 **关联对象 (Associated Objects)** 或继承。
        

### 3. 属性修饰符

- **strong**：增加引用计数，适用于自定义对象和大多数 UI 控件。
    
- **weak**：不增加计数，对象销毁时指针**自动置为 nil**，防止循环引用。
    
- **copy**：创建副本，适用于 `NSString`、`NSArray` 等，防止外部修改原对象影响自身。

## 二、 内存管理深度解析

### 1. 引用计数机制 (MRC & ARC)

- **MRC (手动管理)**：程序员通过 `retain` (+1)、`release` (-1)、`autorelease` 手动控制内存。
    
- **ARC (自动管理)**：编译器 (Clang) 在编译阶段自动插入内存管理代码。
    
- **销毁逻辑**：引用计数归零时触发 `dealloc`。
    

### 2. 循环引用 (Retain Cycle)

- **成因**：两个或多个对象互相持有强引用，导致计数永远不为零。
    
- **典型场景**：Delegate 模式中，Teacher 强引用 Student，Student 也强引用 Teacher。
    
- **解决方案**：将其中一方设为 `weak` 引用。
    

### 3. AutoreleasePool

- **原理**：以栈结构存储对象，当 Pool 销毁时向所有对象发送 `release` 消息。
    
- **手动创建场景**：循环中产生大量临时对象、子类线程操作、处理大数据等。

## 三、 Block 与 集合类型

### 1. Block 内存形态

- **全局 Block (Global)**：不捕获变量，存储在全局数据区。
    
- **栈 Block (Stack)**：捕获变量，存储在栈上，随作用域销毁。
    
- **堆 Block (Heap)**：通过 `copy` 操作将栈 Block 复制到堆上，安全传递。
    

### 2. 变量捕获与 `__block`

- **默认捕获**：值捕获（仅捕获执行时的瞬时值）或引用捕获（对象指针）。
    
- **`__block` 作用**：允许在 Block 内部修改外部的值类型变量，使其从值捕获变为引用捕获。
    

### 3. 深拷贝与浅拷贝

- **浅拷贝 (Shallow)**：仅复制指针，共享同一块内存。
    
- **深拷贝 (Deep)**：复制内容，创建完全独立的副本。
    
- **自定义实现**：对象需采纳 `NSCopying` 协议并实现 `copyWithZone:` 方法。

## 四、 Runtime 运行时黑魔法

### 1. 消息转发三阶段

1. **动态方法解析**：调用 `+resolveInstanceMethod:`，允许运行时动态添加方法实现。
    
2. **快速转发**：调用 `-forwardingTargetForSelector:`，将消息转发给其他能处理的对象。
    
3. **标准转发**：调用 `-methodSignatureForSelector:` 获取方法签名，随后在 `-forwardInvocation:` 中处理 `NSInvocation`。
    

### 2. Method Swizzling

- **核心逻辑**：在运行时交换两个方法的 `IMP`（实现地址）。
    
- **应用**：无侵入式埋点统计、性能监测、修复系统 Bug。
    
- **安全注意**：必须在 `+load` 中执行，且配合 `dispatch_once` 确保仅执行一次。

## 五、 KVC 与 KVO 机制

### 1. KVC (键值编码)

- **原理**：通过字符串间接访问属性。
    
- **`setValue:forKey:` 查找顺序**：`setPropertyName:` (Setter) -> `_propertyName` -> `propertyName` -> 报错。
    

### 2. KVO (键值观察)

- **原理 (isa-swizzling)**：
    
    1. 运行时动态生成中间子类 `NSKVONotifying_原类名`。
        
    2. 将被观察对象的 `isa` 指针指向该新类。
        
    3. 重写 Setter 方法，在赋值前后分别调用 `willChangeValueForKey:` 和 `didChangeValueForKey:` 来通知观察者。
        
- **注意事项**：必须在 `dealloc` 中移除观察者，防止野指针崩溃。
