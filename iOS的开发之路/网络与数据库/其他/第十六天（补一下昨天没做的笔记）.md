### 一、 网络抽象层：原生 `NSURLSession` 封装 🌐

1. 工作原理与生命周期管理
`NSURLSession` 是 iOS 系统的网络引擎。其核心在于将“请求描述”转化为“实际网络 IO”。

* **DataTask 的创建**：通过 `sharedSession` 或自定义配置的 session 对象，使用 `dataTaskWithRequest:completionHandler:` 方法创建任务。
* **Resume 生命周期**：**重点！** 所有的 Task 在创建后默认是 `Suspended`（挂起）状态，必须调用 `[task resume]` 才能启动网络请求。
* **请求头配置**：利用 `NSMutableURLRequest` 的 `setValue:forHTTPHeaderField:` 方法配置 `Content-Type`、`User-Agent` 或 `Token`。

2. 异步并发与线程切换 (Threading Control) 
为了不阻塞 UI（导致界面掉帧或卡死），必须遵循以下原则：

* **后台执行**：`NSURLSession` 的回调默认在系统创建的后台线程执行。
* **主线程回归**：所有涉及 UI 更新（如刷新列表、隐藏加载转子）的操作，必须手动切回主线程。
    Objective-C
    

```
// 典型的线程切换模式
dispatch_async(dispatch_get_main_queue(), ^{
    // 更新 UI 代码
});
```

### 二、 数据解析与映射：JSON 自动化建模 🧩

1. `NSJSONSerialization` 转换逻辑

这是系统原生的解析方案，负责将网络下载的 `NSData` 转化为 OC 原生容器：

* `NSData` ➡️ `NSDictionary` / `NSArray`。
* **注意**：解析时建议使用 `NSJSONReadingMutableContainers` 选项，以便后续对数据进行微调。

2. 标准化错误处理 (Error Handling) 
一个健壮的网络层不仅要看成功，更要看如何优雅地“失败”：

|

| 错误类型<br>      | 判断依据<br>                    | 处理策略<br>                  |
| ------------- | --------------------------- | ------------------------- |
| **网络层错误**<br> | `NSError ` <br>对象存在<br>     | 检查断网、超时（Timeout）<br>      |
| **协议层错误**<br> | `NSHTTPURLResponse` 状态码<br> | 404 (丢失), 500 (服务器错误)<br> |
| **业务层错误**<br> | JSON 中的 `code` 字段<br>       | Token 过期、权限不足<br>         |
