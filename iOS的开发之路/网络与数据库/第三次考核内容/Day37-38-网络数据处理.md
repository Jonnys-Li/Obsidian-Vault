# Day 37-38：网络数据处理

## 概述

本单元涵盖：**断点续传**（Range、resumeData）、**文件上传**（multipart/form-data）、**文件下载**到沙盒、**JSON 解析**与模型转换思路，并结合 NSURLSession/AFNetworking 实践。

## 知识点

### 1. 断点续传

- **原理**：HTTP Range 请求（请求头 `Range: bytes=start-end`），服务端返回 206 与对应片段；客户端把已下载与本次片段拼接。
- **NSURLSessionDownloadTask**：支持取消时拿到 `resumeData`，再次用 `downloadTaskWithResumeData:` 可从断点继续。需将 resumeData 持久化（如写入 Caches），以便 App 重启后恢复。
- **注意**：resumeData 有时效性与版本依赖，部分服务端不支持 Range 则无法断点续传。

### 2. 文件上传

- **multipart/form-data**：表单上传文件时的 Content-Type，boundary 分隔各字段与文件块。
- **NSURLSessionUploadTask**：可从文件 URL 或 Data 上传；AFNetworking 的 `POST:parameters:constructingBodyWithBlock:` 可方便地拼接 multipart。
- **示例**：在 constructingBodyWithBlock 里 appendPartWithFileURL 或 appendPartWithFileData。

### 3. 文件下载到沙盒

- 使用 NSURLSessionDownloadTask，在 completionHandler 中拿到临时文件 URL，用 NSFileManager 移动到 Documents 或 Caches 并记录路径。
- 下载大文件建议用 Caches，避免占用备份空间。

### 4. JSON 解析

- **NSJSONSerialization**：`JSONObjectWithData:options:error:` 得到 NSDictionary/NSArray；`dataWithJSONObject:options:error:` 序列化。
- **模型转换**：字典 → 模型可手写 `initWithDictionary:` 或使用 MJExtension/YYModel 等；注意类型与 null 判断。

## 注意事项 / 常见坑

- resumeData 仅在部分情况下有效，取消时需用 `cancelByProducingResumeData:`。
- 上传大文件时注意内存，优先用文件流而非整块 Data。
- JSON 解析前判断 data 非空；字典取值做 null/nil 判断，避免崩溃。

## 小结

- 断点续传依赖 Range 与 resumeData 的保存与恢复；下载结果写入沙盒并管理路径。
- 上传用 multipart 与 UploadTask；JSON 用 NSJSONSerialization，模型层可手写或使用第三方库。
- 配套示例提供完整可运行代码，可直接集成或改造。
