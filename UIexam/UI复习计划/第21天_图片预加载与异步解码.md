# 第21天：图片预加载与异步解码

## 核心知识点总结

### 1. 图片预加载

#### 预加载策略
- **提前加载**：在Cell即将显示前，提前加载图片
- **预加载范围**：通常预加载当前可见区域前后各一屏的内容
- **优先级管理**：可见区域的图片优先级最高

#### 实现方式
```objc
// 在willDisplayCell中预加载
- (void)tableView:(UITableView *)tableView willDisplayCell:(UITableViewCell *)cell forRowAtIndexPath:(NSIndexPath *)indexPath {
    // 预加载当前Cell和后续几个Cell的图片
    NSInteger startIndex = indexPath.row;
    NSInteger endIndex = MIN(startIndex + 5, self.dataArray.count - 1);
    for (NSInteger i = startIndex; i <= endIndex; i++) {
        [self preloadImageAtIndex:i];
    }
}
```

### 2. 异步解码

#### 为什么需要异步解码
- 图片解码是CPU密集型操作
- 在主线程解码会导致UI卡顿
- 解码后的图片占用内存较大

#### 实现方式
```objc
- (void)loadImageAsync:(NSString *)imageURL completion:(void(^)(UIImage *image))completion {
    dispatch_async(dispatch_get_global_queue(DISPATCH_QUEUE_PRIORITY_DEFAULT, 0), ^{
        // 在后台线程解码
        UIImage *image = [UIImage imageWithContentsOfFile:imagePath];
        UIImage *decodedImage = [self decodedImageWithImage:image];
        
        dispatch_async(dispatch_get_main_queue(), ^{
            completion(decodedImage);
        });
    });
}
```

### 3. 图片缓存

#### SDWebImage使用
```objc
#import <SDWebImage/SDWebImage.h>

[cell.imageView sd_setImageWithURL:[NSURL URLWithString:imageURL]
                   placeholderImage:[UIImage imageNamed:@"placeholder"]
                            options:SDWebImageRetryFailed];
```

#### 缓存策略
- **内存缓存**：使用NSCache，自动管理内存
- **磁盘缓存**：持久化存储，减少网络请求
- **缓存清理**：根据LRU策略自动清理

### 4. 内存优化

#### 图片内存占用
- 图片内存 = 宽度 × 高度 × 4字节（RGBA）
- 一张1000×1000的图片占用约4MB内存
- 需要及时释放不需要的图片

#### 优化方法
- 使用缩略图：显示时使用小尺寸图片
- 及时释放：Cell不可见时取消加载任务
- 内存警告处理：收到内存警告时清理缓存

## 面试题

### 基础题

#### 1. 为什么图片加载需要异步处理？

**答案：**
- 图片解码是CPU密集型操作，耗时较长
- 在主线程解码会导致UI卡顿，影响用户体验
- 网络请求也是耗时操作，必须在后台线程进行
- 异步处理可以保证UI的流畅性

#### 2. 什么是图片预加载？为什么要预加载？

**答案：**
图片预加载是在图片需要显示之前，提前加载图片数据。
- **好处**：用户滚动时，图片已经加载好，体验更流畅
- **策略**：预加载当前可见区域前后各一屏的内容
- **注意**：不要预加载太多，避免浪费流量和内存

#### 3. SDWebImage的缓存机制是什么？

**答案：**
SDWebImage采用三级缓存：
1. **内存缓存**：使用NSCache，快速访问，自动管理内存
2. **磁盘缓存**：持久化存储，减少网络请求
3. **网络下载**：前两级都没有时，才从网络下载

#### 4. 如何优化图片列表的内存占用？

**答案：**
1. **使用缩略图**：列表显示小图，详情页显示大图
2. **及时释放**：Cell不可见时取消加载任务
3. **限制缓存大小**：设置内存和磁盘缓存的最大值
4. **内存警告处理**：收到内存警告时清理缓存
5. **图片压缩**：使用合适的图片格式和压缩率

### 进阶题

#### 5. 图片解码的原理是什么？为什么解码是耗时操作？

**答案：**
- **原理**：图片文件（JPEG/PNG）是压缩格式，需要解码成位图数据才能显示
- **耗时原因**：
  - 解压缩算法需要大量CPU计算
  - 大图片的解码数据量大
  - 需要将压缩数据转换为RGBA像素数据
- **优化**：在后台线程解码，避免阻塞主线程

#### 6. 如何实现图片的异步解码？

**答案：**
```objc
- (UIImage *)decodedImageWithImage:(UIImage *)image {
    CGImageRef imageRef = image.CGImage;
    CGColorSpaceRef colorSpace = CGColorSpaceCreateDeviceRGB();
    
    size_t width = CGImageGetWidth(imageRef);
    size_t height = CGImageGetHeight(imageRef);
    
    CGContextRef context = CGBitmapContextCreate(NULL, width, height, 8, 0, colorSpace, kCGImageAlphaPremultipliedFirst | kCGBitmapByteOrder32Little);
    
    CGContextDrawImage(context, CGRectMake(0, 0, width, height), imageRef);
    CGImageRef decodedImageRef = CGBitmapContextCreateImage(context);
    
    UIImage *decodedImage = [UIImage imageWithCGImage:decodedImageRef];
    
    CGContextRelease(context);
    CGImageRelease(decodedImageRef);
    CGColorSpaceRelease(colorSpace);
    
    return decodedImage;
}
```

#### 7. 图片预加载的最佳实践是什么？

**答案：**
1. **预加载范围**：预加载当前可见区域前后各一屏
2. **优先级管理**：可见区域的图片优先级最高
3. **取消机制**：Cell不可见时取消预加载任务
4. **数量限制**：不要同时预加载太多图片
5. **网络环境**：在WiFi环境下可以预加载更多

#### 8. 如何处理大图片的内存问题？

**答案：**
1. **使用缩略图**：列表显示缩略图，点击查看大图
2. **图片压缩**：使用合适的压缩率和格式
3. **分块加载**：对于超大图片，使用分块加载
4. **及时释放**：查看完大图后及时释放内存
5. **使用CATiledLayer**：对于超大图片，使用CATiledLayer分块渲染

### 原理题

#### 9. SDWebImage是如何实现图片缓存的？

**答案：**
- **内存缓存**：使用`SDImageCache`类，内部使用`NSCache`
- **磁盘缓存**：使用文件系统，存储在`Library/Caches`目录
- **缓存策略**：LRU（最近最少使用）策略
- **缓存Key**：使用图片URL的MD5值作为key
- **自动清理**：根据内存和磁盘大小限制，自动清理旧缓存

#### 10. 图片内存占用的计算公式是什么？

**答案：**
```
图片内存 = 宽度 × 高度 × 每像素字节数
```
- 对于RGBA格式：每像素4字节
- 例如：1000×1000的图片 = 1000 × 1000 × 4 = 4MB
- 注意：这是解码后的内存占用，文件大小可能更小（因为压缩）

### 实操题1：实现图片列表视图

#### 需求描述
实现一个图片列表，每个Cell显示一张图片，使用异步加载和缓存。

#### 实现步骤

1. **创建图片Cell**
```objc
// ImageCell.h
@interface ImageCell : UITableViewCell
- (void)configureWithImageURL:(NSString *)imageURL;
@end
```

2. **实现异步加载**
```objc
// ImageCell.m
- (void)configureWithImageURL:(NSString *)imageURL {
    // 显示占位图
    self.imageView.image = [UIImage imageNamed:@"placeholder"];
    
    // 异步加载
    dispatch_async(dispatch_get_global_queue(DISPATCH_QUEUE_PRIORITY_DEFAULT, 0), ^{
        NSData *imageData = [NSData dataWithContentsOfURL:[NSURL URLWithString:imageURL]];
        UIImage *image = [UIImage imageWithData:imageData];
        
        dispatch_async(dispatch_get_main_queue(), ^{
            self.imageView.image = image;
        });
    });
}
```

#### 关键代码

```objc
- (UITableViewCell *)tableView:(UITableView *)tableView cellForRowAtIndexPath:(NSIndexPath *)indexPath {

    NSString *imageURL = self.imageURLs[indexPath.row];
    [cell configureWithImageURL:imageURL];
    return cell;
}
```

#### 性能优化点
- 使用异步加载，避免阻塞主线程
- 实现简单的内存缓存

### 实操题2：实现异步图片解码

#### 需求描述
实现图片的异步解码，避免在主线程解码导致卡顿。

#### 实现步骤

1. **创建解码工具类**
```objc
// ImageDecoder.h
@interface ImageDecoder : NSObject
+ (UIImage *)decodedImageWithImage:(UIImage *)image;
+ (void)decodeImageAsync:(UIImage *)image completion:(void(^)(UIImage *decodedImage))completion;
@end
```

2. **实现解码方法**
```objc
// ImageDecoder.m
+ (UIImage *)decodedImageWithImage:(UIImage *)image {
    if (!image) return nil;
    if (image.images) return image; // 动图不解码
    
    CGImageRef imageRef = image.CGImage;
    CGColorSpaceRef colorSpace = CGColorSpaceCreateDeviceRGB();
    
    size_t width = CGImageGetWidth(imageRef);
    size_t height = CGImageGetHeight(imageRef);
    
    CGContextRef context = CGBitmapContextCreate(NULL, width, height, 8, 0, colorSpace, kCGImageAlphaPremultipliedFirst | kCGBitmapByteOrder32Little);
    
    if (!context) {
        CGColorSpaceRelease(colorSpace);
        return image;
    }
    
    CGContextDrawImage(context, CGRectMake(0, 0, width, height), imageRef);
    CGImageRef decodedImageRef = CGBitmapContextCreateImage(context);
    
    UIImage *decodedImage = [UIImage imageWithCGImage:decodedImageRef];
    
    CGContextRelease(context);
    CGImageRelease(decodedImageRef);
    CGColorSpaceRelease(colorSpace);
    
    return decodedImage;
}
```

#### 关键代码

```objc
+ (void)decodeImageAsync:(UIImage *)image completion:(void(^)(UIImage *decodedImage))completion {
    dispatch_async(dispatch_get_global_queue(DISPATCH_QUEUE_PRIORITY_DEFAULT, 0), ^{
        UIImage *decodedImage = [self decodedImageWithImage:image];
        dispatch_async(dispatch_get_main_queue(), ^{
            if (completion) {
                completion(decodedImage);
            }
        });
    });
}
```

#### 性能优化点
- 在后台线程解码
- 避免重复解码（可以缓存解码后的图片）
- 对于小图片，可能不需要解码

#### 实现步骤

1. **在willDisplayCell中预加载**
```objc
- (void)tableView:(UITableView *)tableView willDisplayCell:(UITableViewCell *)cell forRowAtIndexPath:(NSIndexPath *)indexPath {
    // 预加载当前和后续几个Cell的图片
    NSInteger startIndex = indexPath.row;
    NSInteger endIndex = MIN(startIndex + 3, self.imageURLs.count - 1);
    
    for (NSInteger i = startIndex; i <= endIndex; i++) {

    }
}
```

2. **实现预加载方法**
```objc
- (void)preloadImageAtIndex:(NSInteger)index {
    NSString *imageURL = self.imageURLs[index];
    
    // 检查是否已加载
    if ([self.loadedImages objectForKey:imageURL]) {
        return;
    }
    
    // 异步加载
    dispatch_async(dispatch_get_global_queue(DISPATCH_QUEUE_PRIORITY_LOW, 0), ^{
        NSData *imageData = [NSData dataWithContentsOfURL:[NSURL URLWithString:imageURL]];
        UIImage *image = [UIImage imageWithData:imageData];
        
        if (image) {
            dispatch_async(dispatch_get_main_queue(), ^{
                [self.loadedImages setObject:image forKey:imageURL];
            });
        }
    });
}
```

#### 关键代码

```objc
- (void)tableView:(UITableView *)tableView didEndDisplayingCell:(UITableViewCell *)cell forRowAtIndexPath:(NSIndexPath *)indexPath {
    // Cell不可见时，可以取消预加载任务（如果需要）
}
```

#### 性能优化点
- 预加载范围不要太大
- 使用低优先级队列预加载
- 实现取消机制，避免浪费资源

## 常见问题

### Q1: 图片加载很慢怎么办？

**A:**
- 使用图片预加载，提前加载即将显示的图片
- 使用CDN加速图片加载
- 压缩图片大小，使用合适的格式
- 使用缩略图，列表显示小图

### Q2: 图片列表滚动时卡顿怎么办？

**A:**
- 确保图片加载在后台线程
- 使用异步解码
- 在Cell不可见时取消加载任务
- 使用SDWebImage等成熟的库

### Q3: 图片占用内存太大怎么办？

**A:**
- 使用缩略图，列表显示小图
- 及时释放不需要的图片
- 限制缓存大小
- 收到内存警告时清理缓存

### Q4: 如何实现图片的渐进式加载？

**A:**
- 使用SDWebImage的`SDWebImageProgressiveLoad`选项
- 先显示低质量图片，加载完成后显示高清图片
- 或者使用WebP格式的渐进式加载

## 总结

图片加载和优化是iOS开发中的重要主题，掌握以下要点：

1. **异步加载**：所有图片加载都应在后台线程进行
2. **异步解码**：图片解码是耗时操作，需要在后台线程
3. **图片缓存**：使用内存和磁盘缓存，减少网络请求
4. **预加载策略**：提前加载即将显示的图片
5. **内存管理**：及时释放不需要的图片，避免内存溢出
